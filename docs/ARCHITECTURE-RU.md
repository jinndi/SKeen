# Архитектура

> **Note:** Архитектура вдохновлена прочтением одной [китайской статьи](https://lhy.life/20231012-sing-box-tproxy/) по настройке прозрачного прокси (TProxy).

## Redirect

Задействован в режимах `redirect` (TCP) и `hybrid` (TCP), а также для проксирования роутера.

Используется `goto` цепочка **skeen** в `PREROUTING` таблицы `nat`. Если включена политика, вход в неё осуществляется через `connmark match`.

Алгоритм работы:

**Directional Filtering (REPLY optimization)**
  * `ctdir REPLY ACCEPT` - Мгновенный пропуск входящего трафика. Мы проксируем только исходящие запросы, что гарантирует максимальную скорость загрузки и минимальный пинг.

**Excluded Ports**
  * `match-set skeen_exclude_port dst ACCEPT`
  * **Суть:** Если в `skeen.json` указаны порты, которые не надо проксировать - здесь трафик либо улетает напрямую, либо идет дальше на проверку.

**Address Bypass**
  * `match-set skeen_exclude_net4 dst ACCEPT`
  * **Суть:** Игнорим локалку роутера, зарезервированные подсети и пользовательский белый список IP. Пакеты к этим ресурсам идут мимо прокси.

**Excluded FakeIP**
  * `! match-set skeen_fakeip_set4 dst ACCEPT`
  * Если настроен и включен модуль DNS Sing-box, позволяет строить на основе этого маршрутизацию в PREROUTING.
  * **Суть:** Пропускаем трафик к адресам FakeIP (198.18.0.0/15 и fc00::/18) и указанным в файле заданном в пути `firewall.intercept.fakeip.include`, для ускорения маршрутизации минуя ядро Sing-box.

**Connection Marking**
  * Вместо анализа каждого пакета, SKeen «запоминает» решение для всей сессии:
  * **TCP:** Метка `0x12` ставится только для новых соединений (`NEW`). Это экономит CPU, так как ядро не проверяет правила для каждого пакета внутри установленного стрима.

**TCP Redirect Hijack**
  * `connmark match 0x12 REDIRECT`
  * **Суть:** Финишная прямая. Весь выживший TCP-трафик принудительно перенаправляется на локальный порт Sing-Box. В отличие от TProxy, здесь происходит классическая подмена порта на уровне NAT.

## TProxy

Задействован в режимах `tproxy` (TCP & UDP) и `hybrid` (UDP), а также для проксирования роутера.

Используется `goto` цепочка `PREROUTING` в таблице `mangle` под именем **`skeen`**, если включена политика вход в нее осуществляется только по ней через `connmark match`.

Алгоритм работы:

**Socket Fast Path (TCP)**
  * `match socket --transparent` -> `MARK set 0x12 + ACCEPT`
  * **Суть:** Магия для ускорения. Если для пакета уже есть открытый прозрачный сокет в системе, мы просто вешаем метку и пропускаем его сразу к сокету, минуя тяжелые проверки.

**Directional Filtering (REPLY optimization)**
  * `ctdir REPLY ACCEPT` - Мгновенный пропуск входящего трафика. Мы проксируем только исходящие запросы, что гарантирует максимальную скорость загрузки и минимальный пинг.

**DNS TProxy**
  * `tcp/udp dpt:53 TPROXY`
  * **Суть:** Перехватываем DNS-запросы на лету и кидаем их сразу в TProxy порт Sing-Box. Работает, если в конфиге `skeen.json` не включен `firewall.redirect_dns`, иначе просто `ACCEPT` для пропуска дальше по таблицам.

**Excluded Ports**
  * `tcp/udp match-set skeen_exclude_port dst ACCEPT`
  * **Суть:** Если в `skeen.json` указаны порты, которые не надо проксировать - здесь трафик либо улетает напрямую, либо идет дальше на проверку.

**Address Bypass**
  * `match-set skeen_exclude_net4 dst ACCEPT`
  * **Суть:** Игнорим локалку роутера, зарезервированные подсети и пользовательский белый список IP. Пакеты к этим ресурсам идут мимо прокси.

**Excluded FakeIP**
  * `! match-set skeen_fakeip_set4 dst ACCEPT`
  * Если настроен и включен модуль DNS Sing-box, позволяет строить на основе этого маршрутизацию в PREROUTING.
  * **Суть:** Пропускаем трафик к адресам FakeIP (198.18.0.0/15 и fc00::/18) и указанным в файле заданном в пути `firewall.intercept.fakeip.include`, для ускорения маршрутизации минуя ядро Sing-box.

**Connection Marking**
  * Вместо анализа каждого пакета, SKeen «запоминает» решение для всей сессии:
  * **TCP:** Метка `0x12` ставится только для новых соединений (`NEW`). Это экономит CPU, так как ядро не проверяет правила для каждого пакета внутри установленного стрима.

**Final TProxy Hijack**
  * `connmark match 0x12 TPROXY / TPROXY`
  * **Суть:** Финиш. Весь выживший TCP/UDP трафик, который не попал под исключения, принудительно направлен в TProxy порт Sing-Box.

> **Note:** Локальные подсети (список которых доступен в исходном коде) уже добавлены в исключения. Однако, если вам нужно исключить конкретные, их необходимо указать в `skeen.json` либо в конфигурации самого `sing-box`.

## Hybrid

Использует смешанные правила для проксирования роутера: `redirect` (TCP) и `tproxy` (UDP).

## Проксирование роутера

Цепочки, в зависимости от режима фаервола и настроек проксирования роутера (вкл./выкл.), создаются как в `nat`, так и в `mangle` таблицах, привязанных к `OUTPUT` соответственно.

> Обратите внимание: цепочка действует безусловно на весь исходящий трафик самого роутера, кроме трафика `sing-box`. Это означает, что вам необходимо учитывать данный факт при использовании этой функции совместно с другими прокси-инструментами.

Вместо фильтрации по политикам роутера применяется отсеивание процессов, не входящих в группу `skeen` (для предотвращения петель трафика). Правила применяются в следующем порядке:

1. Режим `redirect`, таблица `nat` в `OUTPUT` с именем `skeen_mask`: аналогично правилам Redirect цепочки `skeen`.
2. Режим `tproxy`, таблица `mangle` в `OUTPUT` с именем `skeen_mask`, алгоритм работы:

**Anti-Loop (GID skeen)**
  * `owner GID match skeen ACCEPT`
  * **Суть:** Если пакет создал сам `sing-box`, мы его не трогаем и выпускаем в мир. Без этого правила роутер уйдет в бесконечную петлю.

**Directional Filtering (REPLY optimization)**
  * `ctdir REPLY ACCEPT` - Мгновенный пропуск входящего трафика. Мы проксируем только исходящие запросы, что гарантирует максимальную скорость загрузки и минимальный пинг.

**DNS Hijack (Port 53)**
  * `tcp/udp dpt:53 MARK set 0x12` + `ACCEPT`
  * **Суть:** Если роутер сам хочет что-то зарезолвить, мы вешаем на пакет метку `0x12`. Это заставляет ядро пересчитать маршрут и отправить запрос в Sing-Box. Метка применяется только если не настроен `firewall.redirect_dns` в `skeen.json`; иначе выполняется только `ACCEPT` без маркировки.

**Excluded Ports**
  * `tcp/udp match-set skeen_exclude_port dst ACCEPT`
  * **Суть:** Если в `skeen.json` указаны порты, которые не надо проксировать - здесь трафик либо улетает напрямую, либо идет дальше на проверку.

**Address Bypass**
  * `match-set skeen_exclude_net4 dst ACCEPT`
  * **Суть:** Игнорим локалку роутера, зарезервированные подсети и пользовательский белый список IP. Пакеты к этим ресурсам идут мимо прокси.

**Connection Marking**
  * Вместо анализа каждого пакета, SKeen «запоминает» решение для всей сессии:
  * **TCP:** Метка `0x12` ставится только для новых соединений (`NEW`). Это экономит CPU, так как ядро не проверяет правила для каждого пакета внутри установленного стрима.

**Catch-all (MARK)**
  * `connmark match 0x12 MARK / MARK` - метим всё, что не попало в списки выше.
  * **Итог:** Весь «левый» трафик роутера (обновления, утилиты, скрипты) улетает в таблицу 12, а оттуда - в TProxy.

> **Как это работает физически:**
> Когда пакет получает `MARK 0x12` в `OUTPUT`, ядро делает **Reroute Check**. Оно видит правило `ip rule from all fwmark 0x12 lookup 12` и отправляет пакет на локальную петлю (`lo`). В `PREROUTING` его уже поджидает цепочка **skeen** с правилом входа в неё по `mark match 0x12`, которая делает финальный `TPROXY` на порт Sing-Box. `REDIRECT` происходит в самой `OUTPUT`-цепочке **skeen_mask** - для него нет отдельной цепочки в `PREROUTING`.

3. Режим `hybrid` использует смешанные правила для проксирования роутера: `redirect` (TCP) и `tproxy` (UDP).
4. В остальных режимах можно настроить опцию `service_proxy` в конфиге `skeen.json`, но только для обновления Sing-Box, скрипта SKeen и синхронизации конфигурации через `skeen sync`.
