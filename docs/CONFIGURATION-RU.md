# Конфигурация

### Настройки

> [!NOTE]
> После внесения изменений в файл требуется перезапуск через `skeen restart` или через меню

Файл `/opt/etc/skeen/skeen.json` содержит следующие настройки:

```jsonc
{
  "auto_start": {      //// Конфигурация автоматического запуска SKeen включая Sing-box.
    "enabled": 1,      // Автозапуск SKeen при загрузке роутера (0 = выключено)
    "delay": 0         // Задержка автозапуска в секундах (по умолчанию: 0)
  },
  "policy": {          //// Конфигурация политики доступа в указанном сегменте сети.
    "enabled": 0,      // Включить маршрутизацию на основе политики сегмента (1 - вкл, 0 - выкл)
    "segment": "br1"   // Имя интерфейса сегмента (Bridge), политика которой будет использоваться;
                       // начинается с "br", далее цифра от 0 и больше.
                       // Цифру можно узнать из URL в разделе «Сегменты»,
                       // напр.: http://192.168.1.1/segments/Bridge1  - будет "br1"
                       // Или с помощью команды: skeen iface
  },
  "network": {         //// Конфигурация сети
    "ipv6": 1,         // Включить поддержку IPv6 (0 = выключено)
    "tuning": 0,       // Включить оптимизацию сети через sysctl (1 = вкл).
                       // Если выключено, настройки sysctl сбросятся после перезагрузки.
    "check": [
      "vk.com",
      "ya.ru",
      "77.88.8.8"
    ]                  // Домены или IPv4 для проверки доступности сети (макс. 3)
  },
  "singbox": {         //// Конфигурация Sing-box
    "config": {        // + Файл конфигурации
      "path": "",      // Полный путь либо относительно рабочей папки /opt/etc/skeen
                       // к локальному файлу, либо папке конфигурации Sing-box.
                       // По умолчанию используется файл по пути /opt/etc/skeen/config.json
      "url": "",       // URL-адрес (http:// или https://), откуда будет синхронизироваться
                       // конфигурация командой `skeen sync` по умолчанию (необязательно)
      "split": 1       // Если 1, синхронизируемый конфиг по ссылке (skeen sync) будет разбиваться
                       // на файлы по именам ключей верхнего уровня конфигурации Sing-box.
                       // Доступно только если в path указан путь к папке.
    },
    "api": {           // + Настройки sing-box API для работы команд через прослойку (skeen api)
                       // Требуется sing-box версии 1.14.beta.15 и выше
      "url": "",       // URL к сервису sing-box API, если не указан будет http://127.0.0.1:9999
      "secret": ""     // Секретный ключ API, укажите если задан в конфигурации sing-box.
    },
    "external": {      // + Использование стороннего Sing-box
      "enabled": 0,    // Если 1, используется сторонний бинарный файл Sing-box;
                       // его установка, обновление и удаление будут под вашим контролем.
      "path": "",      // Полный путь к файлу или имя (по умолчанию: /opt/bin/sing-box).
      "config": {      // Файл конфигурации для стороннего Sing-box (необязательно)
        "path": "",    // Аналогично singbox.config объекту выше,
        "url": "",     // будут использоваться его данные если здесь не указаны.
        "split": 1
      },
      "api": {         // Параметры для обращение к sing-box API (необязательно)
        "url": "",     // Аналогично singbox.api объекту выше,
        "secret": ""   // будут использоваться его данные если здесь не указаны.
      }
    }
  },
  "services": {        //// Конфигурация дополнительных сервисов
    "proxy": {         // + Сервис локального прокси для команд update и sync
      "enabled": 0,    // Если 1, используется локальный прокси (127.0.0.1)
      "port": "",      // Порт локального прокси (SOCKS5 или mixed)
      "user": "",      // Имя пользователя для подключения (не обязательно)
      "pass": ""       // Пароль пользователя для подключения (обязательно если указан user)
    }
  },
  "firewall": {        /// Конфигурациия фаервола SKeen (iptables цепочки/правила)
    "intercept": {     // + Правила перехвата в ядро Sing-box

      "dns": 1,        // Перехватывать DNS-запросы в режимах TProxy/Hybrid (0 = выкл),
                       // будет игнорироваться, если настроен redirect_dns (см. ниже)

      "fakeip": {      // Перехват на основе Sing-box FakeIP DNS
        "enabled": 0,  // Если 1, включит FakeIP-пул адресов в перехват Redirect/TProxy,
                       // всё остальное пойдёт напрямую минуя sing-box.
                       // - Необходимо включить firewall.intercept.dns или firewall.redirect_dns
                       //   и настройка DNS секции в json конфигурации sing-box.
                       // - Исключения exclude.port/cidr будут работать в обычном режиме.
        "include": "", // Полный путь к файлу, включающему список IP/CIDR ресурсов (как v4, так и v6).
                       // - Разрешены комментарии после #, пустые строки и пробелы по бокам.
                       // - Предназначен для ресурсов, которые изначально не имели домена и, следовательно,
                       //   не получили FakeIP, но которые необходимо проксировать.
                       // - По умолчанию, если не задано, используется путь /opt/etc/skeen/pure_cidr.list
        "clients": []  // Клиенты (IP-адреса или CIDR), которым необходимо применить FakeIP перехват
                       // Пример: [ "192.168.2.10", "192.168.2.11" ], если [] - используются все.
                       // Для стабильной работы необходимо назначить указанным постоянный IP-адрес,
                       // делается это в интерфейсе Keenetic/Netcraze - вкладка "Списки клиентов"
      }
    },
    "exclude": {       // + Правила исключения из перехвата в ядро Sing-box
      "port": [
        "137:139",     // Порты, исключенные из Redirect/TProxy
        445, 1900      // (80 и 443 порты не добавятся, исключайте только необходимые служебные)
      ],
      "ipv4_cidr": [], // Исключенные подсети IPv4 из Redirect/TProxy
                       // Пример: [ "192.87.1.0/24", "192.12.1.1" ]

      "ipv6_cidr": []  // Исключенные подсети IPv6 из Redirect/TProxy
                       // Пример: [ "2001:db8::/32", "2001:db8::1" ]
    },
    "redirect_dns": {  // + Редирект DNS запросов (как альтернатива перехвата)
      "enabled": 0,    // Если 1, включает редирект DNS-запросов до системных правил
      "to_port": "",   // Порт, на который будут перенаправляться DNS-запросы
      "use_policy": 1  // Если политика настроена, она будет использоваться (0 = выкл)
    },
    "proxy_router": 0, // Если 1, будут проксироваться все сервисы роутера.
                       // Доступно в режимах redirect, tproxy и hybrid;
                       // исключения подсетей и порты исключения учитываются.
  },
  "update": {          /// Настройки обновления (skeen update)
    "singbox": {       // Обновления Sing-box (не работает при singbox.external.enabled=1)
      "enabled": 1,    // Включить проверку обновлений Sing-box (0 = выкл)
      "beta": 0        // Если 1, включает проверку самых свежих версий (alpha, beta, rc)
    },
    "skeen": {
      "enabled": 1     // Включить проверку обновлений SKeen (0 = выкл)
    }
  }
}
```

**Дополнительные пояснения к конфигурации:**

**`policy.segment`** - если вы изменили политику в указанном сегменте при запущенном SKeen, перезапустите его для применения изменений. Если в правилах использования интернет-трафика выбрана политика «По умолчанию» или «Без доступа в Интернет», SKeen будет обрабатывать трафик всего устройства.

**`network.ipv6`** - не включится если провайдер не предоставил IPv6 адрес для выхода в интернет.

**`network.tuning`** - при включении опции скрипт применяет комплекс параметров ядра Linux (`sysctl`), адаптированных под работу высокопроизводительных прокси-сервисов (sing-box).

| **Удержание сессий** | Увеличены таймауты TCP (1200с → 1800с) и UDP (30с → 60с) | Предотвращает разрывы активных соединений при кратковременном простое трафика. |

| **Очереди пакетов** | Увеличены системные очереди (`backlog`, `somaxconn`) | Предотвращает потерю пакетов при резких скачках нагрузки. |

Для возврата сетевых настроек к значениям по умолчанию установите параметр `network.tuning` в `0` и выполните перезагрузку роутера.

**`network.check`** - указывайте только те IP-адреса или доменные имена, которые гарантированно доступны (пингуются) в вашей сети, чтобы скрипт мог корректно проверить соединение и успешно запустить сервисы после перезагрузки роутера.

**`firewall.intercept.fakeip`** - функция построена на работе DNS-модуля sing-box, а значит, он должен быть задействован через `firewall.intercept.dns` либо `firewall.redirect_dns` и настроен правильно (смотрите примеры в папке `examples`). Всё то, что помечается как FakeIP, будет всегда попадать в маршрутизацию sing-box через Redirect и/или TProxy, а всё остальное пойдёт мимо на уровне ядра системы Linux, что может пригодится, если вы в основном используете сервисы внутри страны и хотите разгрузить свой старенький роутер на mips(el), т.к. FakeIP должен использоваться в основном на зарубежном сегменте.

<details>
  <summary>Преимущества по сравнению с GeoIP IPset-фильтрацией по странам</summary>

* **Минимальное потребление RAM:** Метод `geoipset` требует загрузки десятков тысяч российских подсетей в оперативную память роутера для их исключения. FakeIP вообще не хранит гигантские базы IP-адресов. Он работает динамически и «на лету» в рамках одной небольшой локальной подсети, освобождая драгоценную память под нужды системы.

* **Низкая нагрузка на CPU (актуально для mips/mipsel):** Вместо тяжелого поиска IP-адреса по разветвленным хеш-таблицам огромной базы GeoIP для *каждого* сетевого пакета, ядро Linux при FakeIP делает одну мгновенную битовую проверку: принадлежит ли IP к фейк-подсети (например, `198.18.0.0/15`). Все прямые подключения по IP (мессенджеры, игры, P2P), которые не делали DNS-запрос, по умолчанию мгновенно улетают напрямую, вообще не нагружая процессор роутера проверками. В прокси попадет только то, что получило FakeIP по домену, либо точечные IP/CIDR, которые вы сами осознанно внесли в список `include`. Это максимально экономит такты CPU, исключая падение скорости интернета и рост пинга под нагрузкой.

* **Автономность и независимость от обновлений:** Базы GeoIP постоянно устаревают, из-за чего сайты могут ошибочно идти через прокси (или наоборот). FakeIP работает по доменам здесь и сейчас, его не нужно регулярно обновлять, за вас это делает сам sing-box.

* **Точечная фильтрация трафика:** Метод FakeIP направляет в прокси **указанные вами целевые ресурсы** из вашего списка в роутинге DNS sing-box, экономя трафик и ресурс.

* **Встроенная защита от DNS-утечек (DNS Leak):** FakeIP неразрывно связан с DNS-модулем sing-box, поэтому помеченные сайты физически не могут узнать ваш реальный IP-адрес через DNS-запрос провайдера.

* **Чистая архитектура без стороннего софта:** Чтобы заставить GeoIP работать с доменами, другие решения требуют ставить AdGuard Home и т.п., связывать их с ipset и плодить файлы конфигураций. Стоит учитывать, что тот же AdGuard Home - это тяжеловесное приложение, которое по потреблению оперативной памяти и нагрузке на процессор бывает сравнимо с самим прокси-ядром. Запуск такого «зоопарка» на слабом роутере лишен смысла. В SKeen весь функционал FakeIP работает «из коробки» внутри одного компактного бинарника sing-box без лишнего софта и «костылей».
</details>

Это отличное решение, но используйте его с пониманием того, что вам придётся самостоятельно настроить список IP-адресов для сервисов, которые используют прямые подключения по IP (не имеют домена), но вам необходимо их проксировать. К таким сервисам можно отнести:

* **Пулы IP-адресов мессенджеров** - многие соединения идут напрямую к дата-центрам по IP;
* **Голосовые каналы Discord** - WebRTC-трафик часто идет мимо DNS;
* **P2P-сети и торрент-клиенты** - загрузка метаданных и раздачи через трекеры или прямые пиры;
* **Игровые лаунчеры и онлайн-игры** - трафик самих игровых сессий часто идет по прямым адресам, хотя бывают и исключения;
* **Пулы IP некоторых мобильных приложений** - адреса, которые жестко зашиты в код программ (Hardcoded IP).

Адреса таких подключений можно предварительно проанализировать (P2P и т.п. нет смысла) в веб панели во вкладке «Подключения» или «Соединения» (колонка «Хост», целевой адрес) - будет сам айпи вместо домена. Далее ищем в сети актуальные списки нужных IP/CIDR и добавляем их в файл по пути, указанному в параметре `firewall.intercept.fakeip.include` (изменения применятся после перезапуска SKeen через команду `skeen restart`).

Подходит ли вам это решение? Каждый решает сам, исходя из текущих ограничений и личных требований к производительности и безопасности сети.

**`firewall.proxy_router`** - обратите внимание: при включении этой функции будет принудительно использоваться DNS sing-box (если он настроен и включён). Кроме того, если вы не внесли в `firewall.exclude` адреса или подсети (`ipv4_cidr` / `ipv6_cidr`) серверов подключения для встроенных в роутер VPN-сервисов, то трафик к ним также пойдёт через sing-box, создавая лишние накладные расходы.
