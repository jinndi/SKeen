# Инструкция по использованию скрипта

🇷🇺 **Русский** | [🇺🇸 English](./README-EN.md)

## Что делает скрипт

Скрипт распределяет ноды из подписки по группам в шаблон конфигурации sing-box согласно правилам параметра `outbound` и отдает уже готовый полный конфиг sing-box для исопльзования на клиентах SKeen а также для любых официальных графичекских клиентов sing-box.

### Термины

- **Нода** — входящий узел прокси outbounds или endpoints из подписки.
- **Группа** — объект типа `selector` или `urltest`, уже описанный в шаблоне sing-box.
- **Тег** — значение поля `tag` у ноды или группы; по нему скрипт выполняет поиск и фильтрацию.
- **Страновая группа** — динамически создаваемая группа типа `urltest` для нод одной страны.

## Установка Sub-Store

Воспользуйтесь одним или несколькими вариантами:

- [Sub-Store Docker](https://github.com/jinndi/Sub-Store-Docker) — Docker-сборка для VPS/локального развертывания.
- [Sub-Store Desktop](https://github.com/jinndi/sub-store-gui) — десктопная версия для управления подписками.
- [Sub-Store Android](https://github.com/sionnx/SubCase) — Android-версия для мобильного управления.
- [Инструкция на китайском для VPS](https://wiki.repcz.link/substore/install/) — инструкция по установке на VPS.

Предпочтительнее устанавливать на VPS через Docker. Для этого доступ обязательно должен быть по протоколу HTTPS и потребуется настройка реверс-прокси. Более подробная информация доступна по ссылкам выше.

Авторизация осуществляется по параметру, указанному в переменной `SUB_STORE_FRONTEND_BACKEND_PATH`.

## Добавление вашей первой подписки

После успешной авторизации в Sub-Store необходимо добавить подписку:

1. Перейдите в раздел **Подписки** и добавьте подписку или несколько подписок.
2. Заполните как минимум обязательные поля:
   - **Имя (ID)**
   - **Источник** (можно указать URL или вставить ссылки локально в форму ввода, либо и то и другое одновременно — в таком случае ниже в пункте **Слияние источников** выберите **Сначала локальные** или **Сначала удаленные**).
3. Если подписка требует `hwid`, получите параметр к ссылке через команду `skeen headers`.
4. Нажмите внизу кнопку **Сохранить**.

Если у вас несколько подписок, повторите процедуру для каждой из них. После этого создайте подписку типа **Коллекция**: укажите в ней **Имя (ID)**, а в пункте **Выберите включаемые подписки** отметьте ранее добавленные подписки и нажмите **Сохранить**.

Далее ознакомьтесь с разбором параметров в ссылке на скрипт и правилами работы с ними.

## Параметры скрипта (`$arguments`)

- `name` — имя подписки или коллекции Sub-Store, из которой нужно брать ноды.
- `type` — необязательный тип подписки (если укзали `name`). Для коллекции укажите `type=col`, `type=кол` или `type=1`. Для одиночной подписки параметр не нужен.
- `fileName` — опциональный. Имя другого файла для включения из него массива нод из ключей `outbounds` и `endpoints` объекта sing-box.
- `url` — необязательная ссылка на подписку, имеет приоритет над `name`. URL нужно кодировать через `encodeURIComponent`. Например, `http://a.com?token=123` передаётся как `url=http%3A%2F%2Fa.com%3Ftoken%3D123`.
- `includeUnsupportedProxy` — необязательный параметр, включает протоколы, которые обычно не поддерживаются, например SSR и Snell. Пример: `&includeUnsupportedProxy=true`.
- `countryUrltestTolerance` — необязательное значение параметра [`tolerance`](https://sing-box.sagernet.org/configuration/outbound/urltest/#tolerance) для страновых `urltest`-групп, в миллисекундах. Принимается целое число или строка с целым числом от `10` до `500`; если параметр не задан или значение некорректно/вне диапазона, используется `75`. Например, `&countryUrltestTolerance=100`.
- `outbound` — строка правил распределения нод по группам; подробности ниже.

## Правила `outbound`

Параметр состоит из одного или нескольких правил. Каждое правило начинается с `📂`:

```text
📂<имя группы>[🔖<теги нод>][🌐<страны>]
```

Маркеры управляют разными вещами:

- `📂` задаёт регулярное выражение для имени группы в шаблоне sing-box.
- `🔖` фильтрует теги входящих нод: обычные варианты — regex, отдельные флаги, английские названия стран и ISO-коды — страновое распознавание.
- `🌐` выбирает страны списком, не regex. Страновые группы и одиночные страновые ноды добавляются только в совпавшие группы `selector`, не в `urltest`.

Фильтры `🔖` и `🌐` независимы: `🔖` выбирает обычные входящие ноды, а `🌐` отдельно разрешает страновые группы и одиночные страновые ноды.

| Маркер | Если не указан | Если указан фильтр | Отключить явно |
|---|---|---|---|
| `🔖` | Добавляются все ноды | По regex тегов или страновому распознаванию отдельных альтернатив | `🔖🚫` |
| `🌐` | Разрешены все найденные страновые группы и одиночные страновые ноды | Выбираются страны из списка | `🌐🚫` |

`🔖🚫` отключает только обычный отбор нод: `🌐` всё ещё может добавить страновые элементы. И наоборот, `🌐🚫` отключает только страновые элементы, не меняя отбор нод через `🔖`.

После `🌐` укажите страны через `|` или запятую. Для каждой страны можно использовать флаг, английское название или [ISO-код alpha-2/alpha-3](https://ru.wikipedia.org/wiki/ISO_3166-1):

```text
🌐🇩🇪|🇫🇮
🌐Germany|Finland
🌐de|fi
🌐deu,fin
```

Названия и коды стран после `🌐` должны совпадать целиком; это не регулярное выражение. Запятая как разделитель списка поддерживается только после `🌐`.

В `🔖` отдельная верхнеуровневая альтернатива, целиком состоящая из флага, английского названия страны или ISO-кода alpha-2/alpha-3, использует страновое распознавание. Например, `Germany` найдёт немецкие ноды по страновому паттерну, даже если в теге указаны флаг, код или город. Такие значения сравниваются без учёта регистра. Остальные альтернативы остаются regex; `|` внутри скобок, например `(game|premium)`, остаётся частью regex-группы. То же правило действует после `🚫`. Для Великобритании используйте ISO-коды `gb` или `gbr`: `uk` — не ISO-код alpha-2/alpha-3 и в `🔖` считается обычным regex.

### Откуда берутся паттерны и когда нужен regex

| Что указано | Как ищется | Когда использовать |
|---|---|---|
| Отдельный флаг, английское название страны или ISO-код в `🔖` | По паттерну страны из массива [правил `COUNTRY_RULES` в `template.js`](template.js#L4): флагу, кодам, буквальным алиасам из `patternAliases` и специальным вариантам из `patternExtras`/`patternCodePatterns`. Алиасы обычно содержат названия страны на английском и русском, а также названия столиц и городов, если они внесены в правило. | Начинайте с этого способа для обычных страновых тегов. Например, `🔖de` найдёт ноды Германии с флагом, названием, кодом или известным городом в теге. |
| Другой текст или regex в `🔖` | Как regex по тегу ноды. Неизвестные коды и русские названия стран тоже остаются обычными regex, а не специальными страновыми ключами. | Для собственных меток провайдера, нестандартных сокращений и других редких форматов тегов. |
| Список после `🌐` | Сопоставляется с распознанными странами по флагу, названию, алиасу или ISO-коду; это не поиск regex по тегам. | Чтобы разрешить или исключить страновые группы и одиночные страновые ноды. |

Для большинства обычных подписок странового распознавания обычно достаточно — ориентировочно в 90% случаев. Это практическая оценка, а не замер покрытия: результат зависит от того, как конкретная подписка формирует теги. Regex нужен также, когда требуется искать или исключать не страну, а другие части тега — например, провайдера, протокол или тариф (`vless`, `hetzner`, `premium`). Для странового поиска переходите на regex только если в тегах подписки используются нестандартные обозначения, которых нет в паттерне нужной страны.

ISO-коды и названия можно сверить в [таблице кодов ISO 3166-1 в Википедии](https://ru.wikipedia.org/wiki/ISO_3166-1). Смотрите столбцы **«Страна»** (русское название и флаг), **«Английское краткое наименование ISO 3166-1»**, **«Alpha-2 ISO 3166-1»** и **«Alpha-3 ISO 3166-1»**.

Флаг в первом столбце можно использовать как образец; его двухбуквенный код указан в столбце **Alpha-2**. Например, для Германии можно указать любой один вариант: флаг `🇩🇪`, название `Germany`, код alpha-2 `de` или код alpha-3 `deu` — перечислять их все не нужно.

### Примеры от простого к сложному

**1. По умолчанию: все ноды и все страновые элементы**

```text
📂Main
```

Без `🔖` добавляются все обычные ноды; без `🌐` разрешаются все найденные страны. Для страны с 2+ нодами добавляется `urltest`-группа, для одной однозначно распознанной ноды — сама нода.

**2. Только ноды, выбранные regex**

```text
📂Main🔖game🌐🚫
```

Добавятся ноды, в тегах которых встречается `game`. `🌐🚫` отключает страновые группы и одиночные страновые ноды.

Для обычных regex можно использовать альтернативы или группы:

```text
📂Main🔖game|premium🌐🚫
📂Main🔖(game|premium)🌐🚫
```

Оба варианта выбирают `game` или `premium` как regex. Скобки сохраняют `|` внутри regex-группы.

**3. Только страновые элементы, без отбора обычных нод**

```text
📂Countries🔖🚫🌐🇩🇪|🇫🇮
```

Для Германии и Финляндии добавится группа при наличии 2+ нод либо единственная однозначно распознанная нода. `🔖🚫` не отключает эти одиночные страновые ноды: их разрешает `🌐`.

**4. Страновой поиск нод через `🔖`**

```text
📂Main🔖Germany|vless🌐🚫
```

`Germany` найдёт ноды по паттерну Германии, даже если в тегах указаны код, флаг или город; `vless` останется regex. Эквивалентные отдельные страновые варианты — `Germany`, `🇩🇪`, `de` и `deu`. `🌐🚫` не добавит страновые группы поверх нод.

**5. Независимое сочетание отбора нод и стран**

```text
📂Main🔖game🌐🇩🇪|🇫🇮
```

Добавятся ноды с `game` и страновые элементы Германии/Финляндии независимо от того, содержат ли их теги `game`. Если нода подходит под оба условия, она не дублируется при добавлении одиночного странового элемента; при 2+ нодах страна добавляется группой.

**6. Смешанные страновые и regex-условия с исключениями**

```text
📂Europe🔖de|nl🚫hetzner|test|0\.5x🌐🚫
```

`de` и `nl` сначала отбирают ноды по паттернам Германии и Нидерландов, затем из этого набора исключаются ноды с `hetzner`, `test` или `0\.5x` в теге. Исключения не добавляют ноды других стран. Это обычные regex-исключения; `0\.5x` ищет точку буквально. Страновые группы и одиночные страновые ноды отключены через `🌐🚫`.

**7. Страновые исключения и regex-исключения**

```text
📂World🔖🚫ru|🇷🇺|moscow|мск🌐🚫
```

Добавятся все ноды, кроме распознанных как российские и нод, в тегах которых есть `moscow` или `мск`. `ru` и `🇷🇺` исключают по страновому распознаванию; `moscow` и `мск` остаются regex. Положительный шаблон `.*` здесь не нужен: если до `🚫` нет выражения включения, подходят все ноды. Страновые элементы отключены.

**8. Включение и исключение стран через `🌐`**

```text
📂Countries🔖🚫🌐de,fi
📂Other🔖🚫🌐🚫de|fi
```

Первое правило добавляет только страновые элементы Германии и Финляндии; второе — все найденные страны, кроме них. Список в `🌐` принимает `|` или запятую, а названия и коды сопоставляются целиком.

**9. Отключение обоих видов добавления**

```text
📂Empty🔖🚫🌐🚫
```

Не добавятся ни обычные ноды, ни страновые элементы. Если такая группа `selector` останется пустой, скрипт добавит в неё `🔌 DIRECT` (`direct`), чтобы группа не была пустой.

### Несколько правил в одном параметре

Правила можно соединять друг за другом; каждое начинается с `📂`. В редакторе Sub-Store их можно записать в несколько строк. Вставляйте только значение, без `outbound=`.

```text
📂Manual🔖🚫🇷🇺|мос|мск|msk|санкт|spb🌐🇩🇪|🇳🇱
📂Runet🔖ru|🇷🇺|рос|мос|мск|msk|санкт|spb🌐🚫🇷🇺|🇹🇷
📂Torrent🔖torrent|торрент|✅🌐🚫
📂Games🔖hys|hy2|tuic|🎮|🇷🇺🌐🚫
📂AI
```

`Manual` получает все обычные ноды, кроме российских, и разрешает страновые элементы DE/NL. `Runet` выбирает российские ноды, но исключает страновые элементы RU/TR. `Torrent` и `Games` фильтруют только обычные ноды. `AI` без фильтров получает все ноды и все найденные страновые элементы.

Если формируете URL вручную, значение `outbound` должно быть закодировано как параметр URL.

### Разбор правил для предлагаемых шаблонов

Однострочная запись параметра:

```text
outbound=📂Proxy🔖🚫ru🌐🚫ru📂Runet🔖🇷🇺🌐ru📂Torrent🔖torrent|торрент|✅🌐ru📂Games🔖hysteria|hy2|tuic|🎮|🇷🇺|est|fin|lv🌐🚫📂AI🔖🚫🌐🚫ru📂Auto🔖🚫ru🌐🚫
```

Для поля `outbound` в редакторе Sub-Store тот же шаблон можно записать в несколько строк — без префикса `outbound=`:

```text
📂Proxy🔖🚫ru🌐🚫ru
📂Runet🔖🇷🇺🌐ru
📂Torrent🔖torrent|торрент|✅🌐ru
📂Games🔖hysteria|hy2|tuic|🎮|🇷🇺|est|fin|lv🌐🚫
📂AI🔖🚫🌐🚫ru
📂Auto🔖🚫ru🌐🚫
```

- `Proxy` добавляет все ноды, кроме распознанных как российские, и все страновые элементы, кроме российских.
- `Runet` выбирает российские ноды и разрешает российские страновые элементы.
- `Torrent` выбирает ноды по `torrent`, `торрент` или `✅`; отдельно разрешает российские страновые элементы.
- `Games` выбирает ноды по regex `hysteria`, `hy2`, `tuic`, `🎮` или по страновым паттернам России (`🇷🇺`), Эстонии (`est`), Финляндии (`fin`) и Латвии (`lv`). `🌐🚫` отключает добавление страновых групп и одиночных страновых нод.
- `AI` отключает обычный отбор нод и разрешает страновые элементы всех стран, кроме России.
- `Auto` добавляет все ноды, кроме российских, без страновых элементов.

## Создание страновых групп

- Каталог содержит все 249 записей ISO 3166-1 из списка Википедии. Для каждой страны заданы флаг, код ISO alpha-2, код ISO alpha-3 и паттерн для поиска в тегах нод.
- Страновая `urltest`-группа создаётся, если для страны найдено **две или более ноды** и страна разрешена правилом `outbound`. Если найдена ровно одна нода и она однозначно совпала только с одной страной, она добавляется в подходящие `selector`-группы как обычная нода, без создания страновой группы. Если тег этой ноды совпал с паттернами нескольких стран, скрипт не назначает её одиночной нодой ни одной из них.
- Интервал проверок `urltest` рассчитывается по количеству нод: **3 минуты для двух нод**, затем **+30 секунд за каждую дополнительную ноду**, максимум — **30 минут**. Это компромисс между скоростью перепроверки небольших групп и количеством проверок в больших.
- Ноды распознаются по флагам, кодам и названиям. Для некоторых стран в паттернах также учтены распространённые варианты названий и названия городов.
- В массиве [правил `COUNTRY_RULES` в `template.js`](template.js#L4) буквальные варианты названий стран и городов хранятся в `patternAliases` в нижнем регистре через `|`. Добавляйте точные самостоятельные варианты (включая общепринятые сокращения), а не обрезанные основы или демонимы, и не повторяйте один алиас в правилах разных стран. При создании каталога скрипт экранирует алиасы как текст, добавляет общую Unicode-границу и флаг нечувствительности к регистру; повторять границы в каждом алиасе не нужно. Особые регулярные выражения для исключений и кодов задаются отдельно в `patternExtras` и `patternCodePatterns`.
- Тег страновой группы состоит из флага и английского названия страны, например `🇩🇪 Germany`.
- Чтобы страновые группы или одиночные ноды добавлялись по стране, хотя бы одно правило `outbound` должно разрешать эту страну. Без `🌐` правило разрешает все страны; `🌐🚫` запрещает все. Фильтр `🌐` определяет, в какие подходящие `selector`-группы добавятся страновая группа либо одиночная нода; он работает независимо от фильтра нод `🔖`.

## Порядок нод и уникальность тегов

- В группе `selector` сначала остаются элементы, заданные в шаблоне, затем добавляются страновые группы, ноды, выбранные через `🔖`, и одиночные страновые ноды, которых ещё нет в группе.
- Например, для пустой группы и правила `📂Main🔖game🌐🇩🇪|🇫🇮` список будет:

  ```text
  ["🇩🇪 Germany", "🇫🇮 Finland", "game-node-1", "game-node-2"]
  ```

- Если в шаблоне уже были элементы `["template-outbound-1", "template-outbound-2"]`, итоговый порядок будет:

  ```text
  ["template-outbound-1", "template-outbound-2", "🇩🇪 Germany", "🇫🇮 Finland", "game-node-1", "game-node-2"]
  ```

- Теги групп из шаблона не меняются. Теги входящих нод и создаваемых страновых групп проверяются на совпадения друг с другом и с тегами шаблона. При совпадении к новому тегу добавляется числовой постфикс через дефис: `🇩🇪 Germany-1`, `🇩🇪 Germany-2` и так далее.
- Если тег входящей ноды переименован, скрипт также обновляет ссылки на неё в `detour` и `outbounds` других входящих нод.

## Важные особенности

- Страновые группы в шаблоне не задаются: их создаёт скрипт.
- Группы `selector` и `urltest`, заданные в шаблоне, не удаляются. Если группа остаётся пустой или для неё нет правила `outbound`, в неё добавляется `🔌 DIRECT` (`direct`), чтобы она не осталась пустой.

## Проверка логики `outbound`

Из корня репозитория запустите:

```sh
node --test sub-store/template.test.mjs
```

Тесты запускают шаблон на фиктивных данных и проверяют фильтры по умолчанию, смешивание страновых и regex-условий, кириллические regex без учёта регистра, группы, символьные классы, якоря и экранированные `|`, исключения, одиночные ноды и страновые группы, `🔖🚫`/`🌐🚫`, добавление страновых групп только в `selector` и порядок элементов.

## Бенчмарк

Из корня репозитория запустите:

```sh
node sub-store/template.bench.mjs
```

Бенчмарк измеряет полное выполнение шаблона на фиктивных подписках с 100, 500 и 1500 нодами и несколькими размерами конфигурации `selector`. Отдельный сценарий с теми же 500 нодами и 10 группами сравнивает простой `vless` с более сложным regex: группами, символьными классами, экранированным `|`, якорями и исключениями. Оба варианта выбирают один и тот же набор нод. Бенчмарк включает инициализацию шаблона и поиск стран, но не включает сетевую загрузку подписки. Для повторных измерений задайте число прогонов, например `BENCH_ROUNDS=10 node sub-store/template.bench.mjs`. Сравнивайте результаты на одной машине и версии Node.js.

Результат **10 прогонов после одного прогрева** на Node.js `v24.20.0`:

| Сценарий | Ноды | Группы `selector` | Медиана | Минимум |
|---|---:|---:|---:|---:|
| Малый | 100 | 1 | 32,4 мс | 29,8 мс |
| Типичный | 500 | 10 | 103,6 мс | 101,4 мс |
| Большой | 1500 | 30 | 280,1 мс | 276,7 мс |
| Сложный regex | 500 | 10 | 102,6 мс | 100,3 мс |

Это ориентировочные значения: время зависит от машины и версии Node.js.
